# 0.1.1

审阅修复版本。对照宿主 `0.2.2-rc.5` 的专项审阅发现六项缺陷，全部修复；新增 Web 端交接卡片；工程化补齐 PR CI 与宿主版本声明。

## 修复

- **`session_read` 用户正文漏读**：按宿主表面事件形状取文——用户消息读 `data.content`、助手消息读 `data.message.content`，此前统一按后者读取会漏掉全部用户正文。回归测试改用真实发布的 `SessionStore` / `SessionQueryEngine` 构造双角色事件。
- **选择器目标身份丢失**：chip 与纯文本回退均序列化为 `[目标会话：<sessionId>]`，标题仅作显示；同名会话与超长标题不再丢失目标，重命名不影响已插入的标记。
- **投递重复入队**：冷热会话统一走宿主 `sessionController.prompt` 准入，按 `requestId` 去重（覆盖进程重启与消息被领取后的重试）。回执区分 `accepted`（宿主接受）/ `persisted`（宿主确认落盘检查点）/ `unknown`（附 `requestId` 供原参重试）；普通用户来源，正文携带发起方信封与回报地址。
- **`session_create` 失败路径**：首投结果未知时返回可恢复的会话 ID 与 `requestId`，用 `session_send` 补投即可；模型档位写入失败返回 `setup_failed` 及原因，不再弃置已建会话。
- **创建前目录校验**：改用文件系统 `stat`，区分非目录、不存在与权限错误；Workspace 注册失败明确报错，不再静默回退裸 `cwd`。
- **推理档位预检**：模型无档位配置时显式档位在创建前拒绝；补全后的默认档位同样校验，保持会话级模型设置。
- **选择器与准入对齐**：候选改读宿主会话目录快照，排除归档、委派与空白草稿；完整标题与 ID 进搜索字段，突破原生引用候选 50 条上限。

## 新增

- **交接卡片**（Web 端）：发送或创建成功后，回答下方出现可点击回执卡片直达目标；入站交接消息渲染为收件卡片（「接收自 …」/「由 … 创建」），按宿主回显的 `rpcId` 识别，收起显示首句预览、展开显示完整正文。历史 `session-handoff` 记录仍按宿主原生「收到执行请求」呈现。
- **PR CI**（`.github/workflows/verify.yml`）：PR 与 main 推送运行冻结安装、类型检查、决策校验、构建与测试。
- **宿主版本声明**：`engines.dsh: 0.2.2-rc.5`。

## 文档勘误

- `AGENTS.md` 与 [0.1.0.md](./0.1.0.md)：勘误 `private: true` 失实记载——该字段从未设置，0.1.0 即以无 `private` 形态发布。

## 已知限制

- 交接卡片依赖当前会话已加载的 Chat 视图，历史窗口未包含对应工具结果或正文时不显示。
- 插件不保留会话关系台账：回信不携带结构化交接 ID，发起方无法把回信自动归类到某次投递。

## 验证

- `pnpm run typecheck && pnpm run check:decisions && pnpm run build:all && pnpm test` 全绿（17 条决策记录，4 套测试：smoke / host-contracts / handoff-cards / candidate-picker）。
- Web 端到端验收通过：同名目标选择、投递回执卡片、主动回信、新建与首投、选中后归档拒绝、用户消息读取、创建参数预检（W1–W7），以及同进程与跨宿主重启的 `requestId` 去重。
