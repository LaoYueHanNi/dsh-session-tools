# DR: `cwd` 接受口语目录名，按已登记 Workspace 与可见会话目录解析

Status: implemented

## Problem

用户要新建会话时几乎不会报绝对路径，他说的是「在 alpha 那个项目开会话」「挪到上次那个 checkout」。改造前 `session_create` 只有一条路：把参数当路径，绝对路径原样用，其余相对发起会话目录拼接。于是「alpha」被拼成 `<调用方目录>/alpha`，目录不存在，`workspaceRegistry.create` 抛错后回退成裸 `cwd`，会话要么建不出来，要么落到一个用户根本没指定的地方。

把这件事完全推给模型也不行：模型得先 `session_list`、再挑一条历史会话的 `cwd`、再拼出绝对路径，每一步都可能选错，而且依赖它自发多做一次工具往返。

## Decision

`session_create` 的 `cwd` 先做存在性判定，通过即直接使用；不通过时按**口语名**解析：

- 候选集 = `workspaceRegistry.list()` 的每个 Workspace（`title` 与 `path` 末级段）+ `sessionQuery.listSessions()` 返回的每个会话（其投影标题 + `cwd` 末级段）。用户说「那个会话的目录」和说「那个项目」都能落到同一处。
- 比较键归一化：小写，去掉空格、下划线与连字符；带路径分隔符的参数按「路径后缀」比较，所以 `projects/alpha` 能命中 `/workspace/projects/alpha`。
- 唯一命中且目录真实存在 → 使用该目录；多命中 → 抛错并列出候选路径；零命中 → 抛错、列出已知目录（与输入有包含关系的排前面），并在存在发起会话目录时提示「省略 `cwd` 用它」。
- 存在性判定优先走 `workspaceRegistry.resolveByPath`（路径不存在会 reject），没有该服务时退回 `node:fs/promises` 的 `stat`。

工具描述与 `cwd` 参数描述同步写明三种给法与歧义行为，让模型知道可以直接把用户嘴里的名字传进来。

## Alternatives considered

- **让模型自己先 `session_list` 再拼绝对路径** —— 输在把可靠性押在模型的工具编排自觉上；名字匹配只是一次本地集合比较，成本更低，失败消息还能反向纠正模型。
- **新增一个独立的目录候选工具（如 `session_dirs`）** —— 输在多一次往返和一个新的工具面；在创建路径上顺带解析已经够用。
- **匹配失败时静默回退到发起会话目录** —— 输在会悄悄把工作建到用户没说的位置，比明确报错更糟。
- **用编辑距离做模糊匹配** —— 输在多命中概率高、解释成本高；归一化键的精确匹配加路径后缀匹配已经覆盖 `alpha`、`Alpha Work`、`projects/alpha` 这几种真实写法。

## Consequences

- 代价：存在性判定把 `resolveByPath` 的任何 reject 都当作「目录不存在」，权限错误会被误判成不存在，最终以「未知目录」报错；匹配范围只限已登记 Workspace 与可见会话目录，一个从没进过侧边栏的新目录仍必须给路径；Host 半新增了一处运行时 import（`node:fs/promises`），它是 Node 内置模块，不参与依赖解析。
- 换来：用户说「在 alpha 那个项目建个会话」或「在那个会话的目录再开一个」都能直接落到正确目录；失败时错误里带候选与继承提示，模型一次就能改对。冒烟测试覆盖了标题命中、末级段命中、路径后缀命中、会话标题命中、歧义、未知名与相对路径七条分支。
