# DR: 在聊天回合末尾展示可跳转的交接回执

Status: implemented

## Problem

发送消息和创建会话的结果出现在工具过程里。用户在读完回答后需要到侧边栏重新定位目标，相似会话标题也会影响定位。

## Decision

客户端在 `conversation.chat.turnTail` 注册交接卡片。卡片从当前会话已经加载的 Chat 视图中读取该回合的成功工具结果，包括嵌套工具调用。显示目标标题和工具确认的回执。用户点击后用结果中的会话 ID 和宿主导航打开目标。中英文文案跟随客户端语言，样式使用宿主卡片配色。

在 dsh `0.2.2-rc.5` 中，公开导航接口 `uiWorkspace.openSession` 只接受会话目标。点击发件卡片会打开目标会话，落点由宿主决定。

`session_send` 和 `session_create` 的工具说明要求模型在纯交接成功时一句话确认。本轮执行的实际成果、用户要求的细节及异常仍由模型说明。宿主的工作步骤折叠设置负责收起过程回复。

接收端通过 `conversation.chat.user.before` 识别宿主 `source.rpcId` 中插件生成的 `session-send:` 和 `session-create:` 请求。识别成功的普通消息行默认收起正文，展开时复用已加载的宿主正文。样式作用域为该行，隐藏普通用户行的操作栏。宿主保留原有来源和请求 ID，去重语义继续由[投递决策](2026-11-21-prompt-admission-receipts.md)定义。

历史记录的旧格式是 `source.kind = "session-handoff"`、`form = "relay"`。宿主的 `turnTriggerDetails` 把这类 non-human message 归为回合触发器，只渲染「收到执行请求」，不生成普通用户消息行，因此 `conversation.chat.user.before` 不会执行。插件保留的 `session-handoff` 徽标分支只适用于仍以用户行呈现的旧记录；本版不接管这类 turn trigger，历史消息维持宿主原生标题。

收件和发件卡片共用图标、字阶、边框和间距。收件卡片按请求 ID 从接收会话当前已加载的 Chat 视图定位正文。标题展示交接信封里的发起会话名称，副标题展示正文首行的第一句话，最长 120 个字符。未附发起会话时使用通用标题，尚未加载对应正文时仅显示标题。原始正文及主动回报地址在展开后可见。

发件卡片标题使用「发送到」加会话名。目标会话中的 `session-create:` 首投显示「由 … 创建」，缺少发起会话名称时显示「会话已创建」。`session-send:` 投递显示「接收自」加会话名。所有方向共用同一套中性强调标签：沿用宿主次级描边、浅色底和主文字色，不引入额外语义色；标签字号为 12px，小于标题的 14px，字重为 500。长名称在标签内截断，悬停显示完整名称。两个插槽使用宿主提供的 `t`，随界面语言切换重绘。收件卡片的箭头在收起时朝下，展开时朝上。

## Alternatives considered

**通用工具结果卡片。** 它继续服务于查看过程细节，折叠执行过程时用户较难找到交接结果。

**由模型生成卡片标记。** 工具结果已经记录目标身份和回执，允许模型再生成一次会增加结果与卡片不一致的可能性。

**按正文信封识别入站交接。** 粘贴或引用信封的用户正文也会命中。请求标记只用于展示，使用宿主持久化的来源字段。

**接管历史 turn trigger。** 通过 `conversation.chat.node` 重绘 `ContextMessageNode` 且 `source.kind === "session-handoff"` 的记录，可以让旧会话也显示交接卡片。但这需要复刻宿主的 turn trigger 展开、历史分页和来源语义，并可能覆盖宿主未来的统一入口；旧记录不可变，收益只限存量会话，风险高于收益，因此不实施。

**回填旧 source。** 把历史 `session-handoff` 改写成新的 `user` 加 `rpcId` 结构可以让所有记录走同一路径，但会改写持久化历史，并重新解释请求 ID 与去重语义，因此不实施。

**定位到本次投递。** 等宿主提供公开的消息级导航接口后再接入。点击回执时用目标会话 ID 和请求 ID 定位对应的收件卡片，由宿主加载所需历史。消息仍在排队或定位失败时，回退到打开目标会话。单向交接契约继续适用。

## Consequences

卡片可以随已加载的会话记录重放，并依赖宿主 Chat 视图保留工具名称和结果内容。卡片展示的回执只覆盖目标对投递的接受，任务结果通过接收方主动回信交付。历史记录窗口没有包含足够结果数据时，卡片不显示。

收起样式依赖 rc.5 用户行的装饰插槽和正文标记。宿主的 `steering` 行没有这个插槽。工具说明可引导回答长度，实际措辞由模型生成。

历史 `session-handoff` 会话仍显示「收到执行请求」，与新版卡片展示不一致。这是宿主按来源字段走 turn trigger 分支的结果，不是缓存或投递时机问题。新格式消息不受影响。
