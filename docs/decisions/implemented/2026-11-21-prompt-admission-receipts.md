# DR: 交接使用宿主 prompt 准入及请求标识

Status: implemented

## Problem

直接向热会话收件箱写入后再等待落盘，落盘失败时重试会产生重复消息；冷热路径的回执也不一致。

## Decision

冷热目标统一使用宿主 `sessionController.prompt`，由宿主以请求 ID 查重。返回 accepted 只表示宿主接受；异常返回 unknown 和请求 ID，调用方重试同一逻辑交接时保留该 ID、目标和消息。创建后的首投结果也返回会话 ID 与请求 ID。发起方不读取或轮询目标。

如果会话已创建但请求的模型未能设置，工具返回 `setup_failed`、实际会话 ID 和失败原因。此时首条消息尚未提交，用户可以先修正会话配置，再决定是否继续投递。

宿主从内存和已持久化的收件箱及用户事件恢复请求记录。准入成功后，插件通过 `sessions.flush` 请求一个落盘检查点。只有宿主确认时才返回 `persisted: true`，落盘状态未知时保留原有准入回执。崩溃后的去重取决于事件是否已落盘。目标会话使用宿主普通用户来源，正文携带来源和主动回报地址。接收端展示见[交接卡片决策](2026-11-21-handoff-receipt-cards.md)。

## Alternatives considered

- **直接调用 live Agent 并 flush** —— flush 失败之前消息可能已经入队，插件无法安全判断重试。
- **为插件自建收据** —— 无法与宿主入队原子提交，仍有崩溃窗口。

## Consequences

- 代价：失去 session-handoff 来源徽标；未持久化的崩溃窗口不能保证去重。
- 换来：宿主已有的请求去重覆盖冷热切换和已记录的已领取消息；未知结果不误报成功。
