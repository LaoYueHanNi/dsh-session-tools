# DR: 用客户端会话目录构建可投递选择器

Status: implemented

## Problem

原生引用候选默认上限 50 条，弹层只过滤首次加载的候选；它还可能列出归档或委派会话，选择后投递却会被拒绝。标题截断也使超长标题后半部分无法搜索。

## Decision

选择器读取 rc.5 的 `sessions.list` 的 `ids` 和 `byId` 元数据，并结合 `workspaces.list` 的归档集合；两个基线均就绪后，按目录顺序列出全部非自身、非归档、非委派且非空白的会话。空白会话是侧边栏可复用的草稿，不放进选择器；`session_list` 是通用发现面，可包含空白会话以及标有归档或委派状态的行，直接按 ID 投递空白会话仍受支持。发送时重新检查自身、归档和委派状态，以处理打开选择器之后状态发生变化的情况。

弹层采用 rc.5 默认的本地子串搜索：完整标题和稳定 ID 放入详情搜索字段，即使显示标题被截断也能匹配。整个候选路径只读取会话和 Workspace 元数据，不读取目标正文。基线未就绪时不提供候选，避免将尚未确认的归档会话误列为可投递。

## Alternatives considered

- **继续使用原生引用候选** —— 空查询有 50 条上限且包含不可投递对象，弹层也不会随搜索文本重新请求。
- **服务端动态搜索** —— rc.5 的 `popupSelect` 不提供查询变化回调，无法在现有弹层中接入。

## Consequences

- 代价：弹层每次打开时载入完整客户端目录；极大的目录会增加本地过滤成本，基线未就绪时需重新打开弹层。
- 换来：可按标题或 ID 搜索超过 50 条的候选，且选择时排除已知不可投递和空白草稿，不引入目标内容读取。
